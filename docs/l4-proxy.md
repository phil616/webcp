# 四层代理

在「网站 → 四层代理」创建规则，选择 TCP 或 UDP，填写宿主机监听 IP/端口，以及单个目标域名或 IP/端口。支持创建、编辑、搜索、筛选、启停和删除，操作使用与网站列表相同的 1Panel 组件。

例如将宿主机 `127.0.0.1:15432/TCP` 转发至 `host.docker.internal:5432`。目标从 OpenResty 容器内访问：`127.0.0.1` 是容器自身，`host.docker.internal` 映射宿主机网关；宿主服务需要监听网关或其他容器可达地址，不能仅监听宿主机回环地址。也可以填写容器可达的局域网 IP 或域名。目标域名在应用时解析，DNS 变化后重新应用。

监听地址只能是宿主机 IP，`0.0.0.0` 表示所有 IPv4 地址；IPv6 直接输入 `::` 或 `::1` 等地址，不加方括号。实际 IPv6 发布还依赖 Docker 和宿主机网络配置。监听和目标端口均为 1–65535。同协议的重叠监听会被拒绝；TCP 与 UDP 可以共用同一宿主端口。通配监听采用保守冲突检查，IPv4/IPv6 通配地址均不能与同端口的其他同协议监听共存。HTTP/HTTPS、自定义网站端口及启用 HTTP/3 时的 UDP 发布端口也参与冲突检查；其他进程占用的端口由 Docker 启动检查发现，失败会回滚。

高级设置提供连接超时（默认 10 秒）、会话空闲超时（默认 600 秒）、UDP 预期响应数（GUI 默认 1，0 表示不等待响应）和向 TCP 后端发送 PROXY protocol。只有后端支持 PROXY protocol 时才能启用，否则后端会收到无法识别的协议头。TCP 支持半关闭和后端 socket keepalive。UDP 是有超时的会话转发，不提供广播或组播代理。

TCP 按字节透传，因此可转发 TLS 和 mTLS；证书、握手与客户端认证由目标服务处理。四层规则不终止 TLS，不绑定网站证书或 Lua HTTP 阶段代码；现有网站仍可独立管理 HTTPS/mTLS。

每条规则仅有一个目标，保留项目原有的功能范围：不增加负载均衡、PHP、运行环境、密码访问或流量限制。

## 应用与回滚

- 引擎停止时，保存只修改草稿；点击状态条「启动」或「校验并应用」后生效。
- 引擎运行时，保存自动校验并应用。目标、超时和 PROXY protocol 修改通常只重载 OpenResty。
- 新增、启停、删除或修改监听的变更可能改变 Docker 发布集合，需要替换托管容器。规则内部端口由排序分配，增删也可能调整映射。这会短暂中断所有网站与代理连接，列表上方持续提示。
- 切换失败时恢复旧容器、旧 current 和运行状态；草稿保留供修正。切换中管理器进程退出，下次启动按日志恢复提交前状态。不要手动删除 runtime/replace-journal.json。
- 旧版本容器首次应用会重建一次，增加动态端口管理与 host-gateway 支持。自选镜像需带 stream 模块及 Nginx 1.21.4+ 的 proxy_half_close 支持。

四层规则与网站、证书、Lua、错误页面一起进入本地和 S3 完整备份；恢复后引擎保持停止，需要检查监听地址及端口是否适用于当前宿主机后重新应用。旧配置和旧备份没有 streams 字段时按空列表加载，无需手工迁移。
